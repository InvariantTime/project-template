# Product documentation

- [Project context](project.md): purpose, scope, and open product questions.
- [Domain glossary](glossary.md): canonical conceptual meanings.
- [Architecture](architecture.md): implemented structure and meaningful constraints.

These pages initially describe the reusable template. Replace their domain content when adopting it for a product. Do not silently treat example or proposed concepts as accepted product decisions.

Development procedures live in [`.dev/docs/`](../.dev/docs/workflow.md). GitHub Issues hold tasks, acceptance criteria, and task status.
